# 图书馆预约系统 · 座位预约小程序

微信小程序原生框架实现的图书馆座位预约系统。**纯前端**，无需后端、无需数据库，导入微信开发者工具即可运行。

- 技术栈：微信小程序原生框架（WXML / WXSS / JS）
- 数据层：`wx.setStorageSync` 本地持久化，模拟后端接口
- 页面数：5 个页面 + 3 个自定义组件
- 开发工具：VSCode（写代码） + 微信开发者工具（预览调试）

---

## 一、快速开始

### 1. 用 VSCode 打开项目

用 VSCode 打开 `study-room-miniprogram` 文件夹即可。建议安装扩展 **minapp**（WXML 语法高亮）。

### 2. 导入微信开发者工具

1. 打开微信开发者工具 → 选择「小程序」→ 点击 **导入项目**
2. 目录选择 `study-room-miniprogram`
3. AppID 处点击 **「测试号」**（或填你自己的 AppID）
4. 后端服务选择 **「不使用云服务」**
5. 点击导入 → 编译

> `project.config.json` 里的 `appid` 目前是 `touristappid`（游客模式），有正式 AppID 时替换掉即可。

### 3. 无需任何额外配置

打开就能用。首次进入是未登录状态，可以在登录页填写学号和昵称，也可以点「暂不登录，先逛逛」先浏览座位。

## 三、功能清单

| 模块 | 功能 |
|---|---|
| 登录页 | 学号 + 昵称输入、用户协议勾选、表单实时校验、登录后自动返回并续接刚才点的座位 |
| 首页 | 未来 7 天日期切换、2~8 层楼层切换（每层显示剩余座位数）、座位地图、实时空位统计、下拉刷新 |
| 选座 | 点击空位弹出时段面板、多选时段（最多 2 个）、**今天已过时间的时段不可预约**、**同一时段跨楼层不可重复预约**、已占时段自动置灰并标注原因 |
| 我的预约 | 全部 / 进行中 / 已完成 筛选（带数量角标）、取消预约（进行中与已完成均可，取消后记录从列表移除）、跳转详情；**未登录时不展示任何预约信息** |
| 详情 | 6 位签到码（点击复制）、预约信息、取消预约 |
| 个人中心 | 登录 / 退出登录、累计预约次数、自习时长、进行中数量、重置数据（清空全部预约，列表归零） |

**座位四种状态**：空闲（白底绿字）、已预约（灰底灰字）、我的（绿色渐变填充）、维修（浅红虚线框）。

## 六、答辩讲解要点

### 1. 项目一句话介绍

> 这是一个校园自习室的在线选座预约小程序。学生按日期、楼层查看实时座位图，点击空位选择时段完成预约，生成签到码到现场终端签到。数据用本地存储模拟，聚焦前端交互与工程化。

### 2. 技术亮点（挑 2–3 个讲透）

**① 座位状态用确定性伪随机，而不是 `Math.random()`**

同一个「楼层 + 日期」必须每次生成完全一样的座位状态，否则用户每次进页面看到的空位都在变，体验会很怪。

实现：先对 `"A2026-10-19"` 做字符串哈希得到种子，再用线性同余公式 `(seed * 9301 + idx * 49297) % 233280` 生成 0~1 的伪随机数，按阈值划分空闲 / 已约 / 维修。

```js
// utils/mock.js
function hash(str) {
  let h = 0;
  for (let i = 0; i < str.length; i++) h = (h * 31 + str.charCodeAt(i)) | 0;
  return Math.abs(h);
}
```

**② 组件化拆分，组件保持无状态**

`seat-map` 组件只负责「把座位数组画出来 + 把点击的座位抛出去」，**不判断这个座位能不能点**。业务规则（维修不能点、已约不能点）全部留在页面里。

```js
// components/seat-map/index.js
this.triggerEvent('select', { seat: seat });
```

好处：同一个座位图组件，将来放到「管理端查看占用情况」的页面里可以直接复用，因为它不依赖任何业务判断。

**③ 数据层单独抽象**

页面里从来不直接写 `wx.getStorageSync`，全部通过 `utils/store.js` 的 `getAll / add / update / remove` 操作。

好处：将来接真实后端，只需要把这一个文件里的 5 个函数改成 `wx.request`，页面代码一行都不用动。这是**面向接口编程**的实际应用。

**④ 弹层动画用 transform 而不是改 height**

```css
.panel {
  transform: translateY(110%);
  transition: transform 0.28s cubic-bezier(0.2, 0.8, 0.3, 1);
}
.panel--on { transform: translateY(0); }
```

`transform` 由 GPU 合成，不触发重排（reflow），在低端安卓机上比动画 `height` 流畅得多。

**⑤ 顶部背景图用 `<image>` 而不是 WXSS 的 background-image**

小程序的 WXSS **不支持本地图片路径**作为背景（只能写网络图片或 base64），所以顶部插画用绝对定位的 `<image mode="aspectFill">` 铺满容器，再叠一层上浅下深的渐变蒙层保证白色标题可读。

这样写还有两个好处：图片走 image 组件，支持 `aspectFill` 等比裁剪；将来换成网络图只需改 `src`。

**⑥ 登录态独立成 auth.js，页面不直接碰 storage**

登录态的所有读写都收在 `utils/auth.js`，对外只有 5 个方法：`getUser / isLoggedIn / saveUser / login / logout`。

登录走的是真实链路的前半段：`wx.login()` 拿临时 code，真实项目里要把 code 发给后端换 openid 和自定义 token，这里用本地假数据代替，接口形态保持一致，将来接后端只改 `login()` 里 resolve 的内容。

页面层的用法很轻：

```js
if (!auth.isLoggedIn()) {
  this.requireLogin(seat);   // 跳转登录页
  return;
}
```

登录页是独立页面 `pages/login`，表单校验规则写在 `validate()` 里：学号 6–12 位纯数字、昵称非空、必须勾选协议，三者同时满足才点亮登录按钮。

**登录后续接选座**是这里最值得讲的一点：未登录时点座位，会把座位存进 `app.globalData.pendingSeat`，再跳转登录页；登录成功 `navigateBack` 回首页，首页的 `onShow` 检查到这个待处理座位就自动把时段面板打开。用户不会因为跳了一次登录页就丢失刚才的选择。

### 3. 可能被问到的问题

| 老师可能问 | 怎么答 |
|---|---|
| 数据存哪？ | `wx.setStorageSync`，单个小程序上限 10MB。这是演示方案，真实项目应放服务端。 |
| 过了时间的时段还能约吗？ | 判定口径是「时段是否已结束」，而不是「是否已开始」。16:00-18:00 在 17:59 仍可预约，18:00 起置灰标注「已过时段」。未来日期不受当前时间影响。提交前会再校验一次，防止面板开着时跨过截止时间。 |
| 没登录能看到预约记录吗？ | 不能。「我的预约」列表、个人中心统计、座位图的「我的」标记、预约详情页四处都做了登录态判断，未登录一律为空或直接拦截。数据仍在本地存储里，重新登录后自动恢复。 |
| 一个人能不能同时占两个座位？ | 不能。判定口径是「同一人 + 同一日期 + 同一时段」，不区分楼层。实现上 `store.mySlotMap(date)` 会汇总我在当天所有座位上的已占时段，时段面板按它置灰，提交前再校验一次防绕过。 |
| 两个人同时抢同一个座位怎么办？ | 前端解决不了，必须后端加锁。可以用数据库乐观锁（`update ... where version = ?`）或 Redis 分布式锁，把「查空位 + 写入」做成原子操作。这个项目因为是单机演示，所以没做。 |
| 为什么不用 Taro / uni-app？ | 实训要求是掌握小程序原生能力，用框架会屏蔽掉 `setData`、生命周期这些底层机制。原生写一遍，再用框架会更清楚框架帮你做了什么。 |
| 登录用的什么方案？ | `wx.login` 拿 code，真实项目由后端换 openid 并签发 token。没用 `wx.getUserProfile`——这个接口 2022 年后已收回，现在拿头像昵称要用「头像昵称填写能力」（`open-type="chooseAvatar"` + `input type="nickname"`）。 |
| 座位图为什么固定 8 列？ | 保证各楼层行列对齐，视觉上更整齐。如果要支持不同布局，把 `COLS` 改成楼层配置里的字段即可。 |
| 有什么可以优化的？ | ① 座位超过 200 个时用虚拟列表（只渲染可视区域）② 时段选择改成滑动选择器 ③ 加骨架屏减少白屏 ④ 预约成功后的数据改为服务端返回 |

### 4. 如果老师问「你还能加什么」

按难度从低到高：座位收藏 → 常用座位推荐 → 扫码签到（`wx.scanCode`）→ 违约记录与信用分 → 管理员端（发布维修、查看占用率热力图）。

## 七、二次改造建议

如果要把这个项目改成自己的题目，改动成本最低的三处：

1. **换场景**：改 `utils/mock.js` 里的 `FLOORS`（楼层名与每层座位数）、`utils/util.js` 里的 `SLOTS`（时段）、页面文案。比如改成「实验室设备预约」「琴房预约」「会议室预约」，业务逻辑完全复用。
2. **换配色**：只改 `app.wxss` 顶部的 CSS 变量（`--c-primary` 等），全站配色一次性换掉。
3. **加一个自己写的页面**：比如「预约日历」用 `calendar` 组件展示一个月的占用情况，这是很好的加分项。
